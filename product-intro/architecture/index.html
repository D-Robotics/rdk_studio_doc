1.2 核心架构

日常使用时，先区分客户端、工作台 Agent 和板端 Agent。

部分职责
RDK Studio 客户端项目、设备连接、文件、终端、烧录与工具界面
工作台 Agent使用 Moss 或 DSH 处理任务，结合项目、附件和允许使用的工具推进工作
模型服务为 Agent 提供模型响应，按服务商、模型名称、API Key 和 Base URL 配置
板端 OpenClaw部署在开发板上，提供板端对话与技能

一条任务怎样运行​

  1. 选择项目，确认工作位置；需要操作设备时确认目标设备在线。
  2. 查看当前任务引擎，选择执行、计划或 Spec 工作方式。
  3. 输入目标，按需附上日志、截图、文件或工作区引用。
  4. Agent 分析并使用当前引擎支持的工具；需要确认时显示审批或澄清提示。
  5. 查看回复、实际输出、文件改动和验证结果。需要查看已有执行记录时，打开该条消息的更多菜单。

停止任务不会自动撤销已经完成的文件或设备变更。

引擎绑定​

Moss 和 DSH 是任务运行引擎，不是模型服务商。到 设置 → AI 模型与服务 → 运行引擎 修改新任务默认值；输入区的引擎标识可跳转到该设置。

已有任务继续使用原引擎。DSH 不可用时会显示原因，不会自动换成 Moss 接管同一任务。要改用另一引擎，请调整默认值后新建任务。

运行形态​

形态使用边界
桌面客户端使用电脑本机服务和系统集成，可提供直接烧录、本机模型等能力
本地 Web / 自托管 Web浏览器连接对应服务；路径和工具权限由服务所在环境决定
公网 Web Cloud按账号隔离用户数据，限制服务器本地文件、宿主操作与部分设置

网页版访问局域网设备可能需要本地连接桥、VPN 或可达网络；它不会仅凭浏览器页面获得电脑的全部设备权限。

设备和本机相互独立​

本机项目不依赖开发板在线。板端命令、文件和服务操作则需要目标设备连接，其他在线设备不会自动替代离线目标。串口用于日志调试，不等同于 SSH 设备接入。

电脑上的 Ollama 与板端 OpenClaw 的模型配置也相互独立，板端必须能访问所填写的模型地址。
