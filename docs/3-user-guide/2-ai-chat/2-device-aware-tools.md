# 3.2.2 设备操作与结果

当你让 Moss 检查设备、运行命令、读取文件或调用 OpenClaw 时，就属于设备操作。这里主要说明：目标设备怎么确定、执行过程在哪里看，以及哪些操作需要你确认。

## 哪些算设备操作

下面这些提问都和设备有关：

- 检查系统版本、磁盘、内存、网络或服务状态。
- 在设备上运行命令、脚本或示例程序。
- 读取、上传、修改设备上的文件。
- 部署 OpenClaw、同步技能或检查板端模型。
- 通过飞书、微信等消息渠道触发设备相关操作。

如果只是问概念、查资料、写方案，不一定需要连接设备。

## 目标设备怎么确定

Moss 会优先参考 AI Dock 输入区里的设备标签。发送前建议看一眼：

- 当前设备是不是你要操作的那台。
- 设备是否在线，SSH 是否已经验证通过。
- 当前项目目录是不是你要处理的目录。

多设备场景中，可以直接在消息里写清楚目标设备，例如：

```text
对 RDK-X5-工位1 检查网络，不要操作其他设备。
```

如果设备标签不对，先切换设备；如果设备离线，可以先让 Moss 做方案，等设备恢复后再执行。

## 执行结果看哪里

根据任务不同，结果可能出现在这些位置：

| 位置 | 你会看到什么 |
|---|---|
| 对话流 | Moss 的解释、步骤、错误原因和下一步建议 |
| 终端 | 设备命令和返回结果 |
| 文件 | 读取或写入的文件路径 |
| 诊断 | 设备状态、网络和服务检查结果 |
| 板端 Agent | OpenClaw 部署、检查、模型或技能相关结果 |

如果结果看起来不符合预期，先确认当前设备标签，再检查终端输出或页面错误提示。

## 哪些操作需要确认

普通查询、读取状态、查看日志通常会直接展示结果。下面这些操作会影响设备或外部环境，继续前会要求你确认：

- 写入、覆盖、删除文件。
- 修改网络、服务或系统配置。
- 停止进程、重启服务或重启设备。
- 向飞书、微信等外部渠道发送消息。
- 部署、卸载或重新部署 OpenClaw、技能等组件。

不确定影响范围时，先切到 **计划**，让 Moss 列出步骤和风险点。

## 串口不等于设备接入

本机串口日志只用于查看启动输出。它不会创建可供 Moss 使用的 SSH 设备，也不能让文件、远程桌面、代码编辑器或 OpenClaw 自动可用。

恢复网络后，请通过 SSH 把设备添加进列表。
