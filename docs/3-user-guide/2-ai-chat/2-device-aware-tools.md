# 3.2.2 设备操作与结果

设备任务先确认 **哪台设备、哪个目录、要得到什么结果**。项目和历史会话可能保留原来的设备绑定，不能只看当前有哪台设备在线。

## 从只读检查开始

```text
检查当前项目绑定设备的网络和磁盘，只读收集信息，先说明异常和建议。
```

设备离线时可以分析已有日志和制定方案；实际板端命令、读写文件和运行服务需要恢复目标设备连接。另一台在线设备不会自动接管。

## 执行与确认

执行模式允许 Agent 使用可用工具完成任务，权限策略仍会检查具体动作和目标。出现审批卡时，核对设备、路径、命令和影响后允许或拒绝。计划模式只做分析，Spec 则先形成可审批的需求与步骤。

Moss 与 DSH 支持的工具可能不同。引擎或操作不可用时，按页面原因处理，不要把“任务已提交”当成操作成功。

## 怎样核对结果

- 先看回答中的完成项、未完成项、失败原因和下一步。
- 需要底层过程时，从消息更多菜单打开 **执行记录**，查看该条消息已有的工具、终端或计划记录。
- 在“打开位置”的终端和文件中核对实际输出与改动。
- 普通复制、分享以回答内容为主，不默认带入内部工具参数或验收记录；代码、命令和协议示例会保留。

停止任务只请求结束后续执行，已经完成的操作不会自动回滚。涉及重新部署、重启或重复写入时，先检查当前设备状态再继续。
