# 3.1.1 设备状态与诊断

工作台通过 **当前工作区** 的现场页、诊断快照、设备在线状态和 Moss 任务信息展示设备状态。

## 工作台会展示什么

| 区域 | 内容 |
|---|---|
| 当前工作区顶部 | 当前设备、远端目录、SSH 验证状态、可执行/只读状态 |
| 现场卡片 | 设备管理、项目空间设置、Git 变更摘要、诊断快照、历史对话 |
| 诊断快照 | 采集设备运行时信息，并可一键送入 Moss |
| Moss 对话 | 根据当前设备信息、项目目录、诊断结果和文件内容回答或执行任务 |

## 诊断快照

点击现场页里的 **诊断快照** 后，RDK Studio 会采集当前设备的运行时信息，并把摘要显示在工作区中。需要进一步分析时，可以把快照送入 Moss。

诊断通常会关注：

| 类型 | 示例 |
|---|---|
| 系统 | 板型、镜像版本、内核、运行时间 |
| 资源 | 内存、磁盘、温度、CPU/BPU 相关状态 |
| 网络 | IP、网卡、外网可达性 |
| 服务 | OpenClaw、代码编辑器、远程桌面、ROS/TROS 相关状态 |

不同板型、镜像和网络状态会导致可采集字段不同。缺失字段会以“未知”或失败原因呈现，不代表设备整体不可用。

## 让 Moss 分析健康状况

在 AI Dock 中描述需求，例如：

```text
帮我看下这台板的整体健康状况，列出最需要优先处理的问题。
```

Moss 会结合当前设备信息、诊断快照和可用功能进行判断。相比直接看一排指标，这种方式更适合排障和给出下一步建议。

## 离线时的状态含义

| 状态 | 含义 |
|---|---|
| 在线 | 可以采集诊断、打开终端/文件、执行设备工具 |
| 待验证 | 需要先验证 SSH，避免沿用缓存误判 |
| 离线 | 可查看历史和缓存信息；设备执行等待恢复 |
| 未连接 | Moss 可做方案，设备相关操作会先引导添加设备 |
