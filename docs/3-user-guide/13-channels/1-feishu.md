# 3.14.1 接入飞书

飞书通道可以把 Moss 接到企业飞书机器人里，团队成员可以：

- 在飞书群中 @机器人，让 Moss 查看状态、分析日志或触发已确认的板端任务
- 在私聊中 1:1 与 Moss 对话
- Moss 的回复和关键操作会在飞书里显示，便于追踪

## 配置项

在 *配置中心 → 消息渠道 · 飞书* 配置以下字段：

![配置中心 · 消息渠道 · 飞书：通道状态、日常用法、应用凭据和连接模式配置](http://rdk-doc.oss-cn-beijing.aliyuncs.com/doc/img/rdk_studio/zh/settings-feishu.png)

| 字段 | 必填 | 来源 |
|---|---|---|
| 应用 ID | 是 | 飞书开发者后台 → 你的应用 → 凭证与基础信息 |
| 应用密钥 | 是 | 同上 |
| 加密密钥 | 否 | 飞书后台 → 事件订阅 |
| 校验令牌 | 否 | 同上 |

应用 ID 和应用密钥是飞书自建应用的凭据。加密密钥和校验令牌用于加强事件校验，按飞书后台提示填写即可。

## 创建飞书自建应用

如果团队还没有飞书自建应用，需要先创建：

1. 进入飞书开发者后台
2. 创建新的"自建应用"，填写应用名称、图标、描述
3. 在 *权限管理* 中开启所需权限：消息读取、发送消息、群组信息等
4. 在 *事件订阅* 中订阅“接收消息”事件，填写回调地址
5. 在 *版本发布* 中提交应用，等待企业管理员审批
6. 审批通过后获取应用 ID 和应用密钥

详细流程请查阅飞书开放平台官方文档。

## 私聊访问控制

| 模式 | 行为 | 适用场景 |
|---|---|---|
| 白名单模式 | 仅指定的飞书用户能与机器人私聊 | 生产环境的强烈推荐 |
| 审批模式 | 任何人发消息，需要管理员审批一次后才能继续使用 | 团队内使用，希望保留简单管控 |
| 开放模式 | 能看到机器人的飞书成员可以直接使用 | 测试环境、明确无敏感操作的场景 |

**生产环境务必使用白名单模式。** 开放模式意味着能看到机器人的人都可能触发 Moss 操作板端，风险很高。

## 用户管理

| 操作 | 路径 |
|---|---|
| 查看已绑定用户 | *飞书 → 用户管理* |
| 审批待处理的配对请求 | *飞书 → 待审批* |
| 移除某个用户 | *用户管理 → 选用户 → 移除* |
| 启动 / 停止整个飞书通道 | *飞书 → 通道开关* |

## 机器人在飞书里能做什么

飞书机器人能干的事情与 AI Dock 几乎相同：

- 查看设备状态："查看 RDK-X5-工位1 的 BPU 占用"
- 文件传输："把 /tmp/log.txt 发给我"（机器人把文件作为附件发到飞书）
- 命令执行："重启 ROS 节点 camera_publisher"
- 使用已加载的相关技能

在飞书中执行高风险命令、文件写入或可能影响设备状态的任务时，机器人会要求你在飞书中二次确认。飞书属于外部通道，所以确认流程会比 Studio 内更严格。
