# 3.4.3 哪些路径不能改

部分敏感路径（如 `/sys`、`/proc`）会限制直接写入，避免误改内核或启动相关文件，导致板端异常。

## 受限的路径

| 路径 | 受限原因 |
|---|---|
| `/sys/` | Linux 内核接口，写入特定文件可能改变内核行为甚至导致硬件异常 |
| `/proc/` | Linux 进程与内核状态接口，写入可能干扰运行中的进程 |
| `/dev/` | 设备节点，错误写入可能导致设备异常 |
| `/boot/` | 系统启动相关文件，错误修改可能导致系统无法启动 |

读取这些路径不受限制，你可以正常浏览和查看内容。只有写入操作会被拦截。

## 例外授权方式

如果确实需要向受限路径写入，有两种方式：

### 方式一：使用终端

在 [3.3 终端](../3-remote-terminal/index.md) 中手动执行命令：

```bash
echo 1 > /sys/class/leds/red/brightness
```

终端会把命令交给板端 shell 执行。请先确认命令和路径，再按回车。

### 方式二：在 AI Dock 中明确授权

在 AI Dock 中描述需求时明确授权，例如：

> "我授权你向 /sys/class/leds 路径写入。请把 LED 红灯打开。"

Moss 收到这种明确授权后，才会继续执行写入。这种方式适用于“想让 Moss 协助操作，但目标路径比较敏感”的情况。

## 拦截行为

当文件拦截写入操作时，会显示如下提示：

```
该路径处于受限范围，无法直接通过文件写入。
请使用终端手动操作，或在 AI Dock 中明确授权。
```

如果写入被拦截，界面会明确告诉你原因，不会显示成“看似成功但实际没写进去”。
