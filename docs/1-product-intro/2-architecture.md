# 1.2 核心架构

RDK Studio 可以先按三个部分理解：电脑上的桌面客户端、在界面里协助你的 Moss，以及需要时部署到 RDK 板上的 OpenClaw。

## 你会接触到的三个部分

| 部分 | 你在哪里看到 | 用来做什么 |
|---|---|---|
| 桌面客户端 | 电脑上的 RDK Studio 窗口 | 添加设备、烧录系统、打开终端、文件、远程桌面、代码编辑器和设置 |
| Moss | 工作台和 AI Dock | 根据当前设备、项目、日志和附件帮你分析问题、生成步骤，并在你确认后执行支持的操作 |
| OpenClaw | 板端 Agent 页面 | 部署到 RDK 板后，用于板端对话、设备技能和更贴近当前设备的任务 |

日常使用时，你不需要记住这些分层。先添加设备，再在工作台里告诉 Moss 你的目标。

如果某个任务需要板端 Agent，RDK Studio 会引导你进入对应页面部署或连接 OpenClaw。

## 什么时候用 Moss，什么时候用 OpenClaw

多数日常开发任务先交给 Moss：看日志、整理步骤、解释报错、打开终端、处理文件、生成排障计划，或把当前页面里的信息串起来分析。

需要板端助手时，再使用 OpenClaw。例如管理板端技能、配置板端模型、让对话直接面向这台开发板，或处理更依赖当前设备的任务。

板端 Agent 页面会展示部署、连接、模型和消息接入等入口；能做什么，请看页面提示。

## 连接关系

RDK Studio 会先通过 SSH 或 Type-C 直连等方式接入设备。接入后，终端、文件、代码编辑器、远程桌面和 Moss 会围绕同一台设备工作。

OpenClaw 部署到 RDK 板端后，也会通过 RDK Studio 建立的连接使用。通常不需要你额外处理复杂的网络配置。

## 发送消息后会发生什么

1. 你在 AI Dock 输入消息，并选择 **执行** 或 **计划** 工作方式。
2. RDK Studio 会把当前页面、当前设备、项目目录、附件和工作区信息提供给 Moss。
3. Moss 会直接回答、继续追问，或给出执行步骤。
4. 如果需要使用终端、文件、设备或 OpenClaw，界面会显示对应动作和执行结果。
5. 涉及写文件、改设备状态、发送外部消息等高风险动作时，界面会要求你确认。
6. 如果任务更适合板端 Agent，Moss 会引导你进入 OpenClaw 相关页面继续处理。

## 执行前后你能看到什么

Moss 可以帮你分析问题，也可以在你确认后使用终端、文件、设备等功能完成操作。关键动作会在界面里留下可见结果，你通常能看到这些信息：

- 终端命令、文件操作、执行结果和错误提示会显示在对话或工作区里，方便你复查。
- 涉及写文件、改设备状态、发送外部消息等高风险动作时，界面会要求你确认。
- 设备离线时，Moss 仍然可以回答知识问题、整理方案和分析已有日志；需要在板端执行的动作，要等设备恢复连接后再继续。
- 串口主要用于查看本机连接到开发板的日志。打开串口不等于把这块板加入设备列表，也不等同于 SSH 设备接入。
- 本地大模型页里的 Ollama 指的是电脑本机服务。板端 OpenClaw 要使用哪个模型，需要在板端 Agent 的模型设置里单独配置。
