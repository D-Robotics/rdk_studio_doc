# 4.1 技能分享

技能可以分享给 **本机 Moss** 使用，也可以部署到 **设备 OpenClaw** 使用；公开分发则通过技能市场 / SkillHub 或普通 Git 仓库完成。

## 分享路径

| 路径 | 适用场景 | 使用方式 |
|---|---|---|
| 技能市场 / SkillHub | 社区公开分享 | 让其他人在技能工坊搜索、预览、添加或部署 |
| Git / GitHub | 团队私有、频繁迭代 | 把仓库链接发给同事，让其从链接生成或导入 |
| NodeHub 案例 | 完整项目 + 配套技能 | 发布项目代码，并让 Moss 从案例链接生成技能 |
| 直接发文件 | 一次性分享 | 发送技能文件，对方在技能工坊中导入 |

## 发布前检查

- 名称清楚，不要用很长的句子。
- 描述说明技能能做什么、不能做什么。
- 关键词覆盖常用说法，方便 Moss 找到它。
- 风险等级要和真实动作一致，尤其是写文件、执行命令、启动后台服务。
- 涉及 BPU、摄像头、GPIO、TROS、RDK 路径时，确认是否只能在 RDK 板上使用。
- 不包含访问密钥、团队内网地址、个人凭据或未授权内容。

## 本机与板端的区别

| 分享目标 | 适合能力 |
|---|---|
| 本机 Moss | 文档检索、代码分析、项目操作、通用 Linux 命令 |
| 设备 OpenClaw | RDK 设备相关操作、板端对话、设备侧通道或更依赖当前设备的任务 |

如果技能只是帮 Moss 更好地分析日志，通常不需要部署到板端；如果技能需要 OpenClaw 在设备上运行，就需要在技能工坊中部署到设备。
